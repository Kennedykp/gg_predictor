## 3. The golden regression suite

`tests/regression/test_poisson_v1_regression.py` holds 12 frozen cases. **Every expected value was generated by executing the current `poisson.py`** — none was hand-computed or "corrected". Comparison uses `rel=1e-12`.

Scenarios covered: balanced teams, strong home attack, strong away attack, weak attack, strong defence, high-scoring environment, low-scoring environment, heavy mismatch, two legacy zero-value cases, minimal intensity, and the ESPN hardcoded `1.35` league-average fallback that production actually uses.

If one of these fails, the correct question is *"what changed in the model?"* — not *"what should I update the number to?"*. Values may only change as part of a deliberate version bump (e.g. `POISSON_V2`), preserving the old values as the historical baseline.

### Proof the net actually catches drift

A safety net that has never caught anything is an assumption, not a guarantee. The suite was verified by temporarily perturbing the λ divisor by 1% (`/ league_avg_goals` → `/ (league_avg_goals * 1.01)`):

```
31 failed, 7 passed
```

`poisson.py` was then restored and confirmed byte-identical by SHA-256. A change small enough to pass unnoticed in review is caught immediately.

The 7 that still passed are the two legacy zero-value cases (λ stays `0.0` regardless of divisor) and the meta-tests — expected, and a reminder that zero-valued inputs carry no signal, which is the substance of GG-001.

Twelve tests deliberately assert behaviour that Epic 0 identified as **wrong**. They are not endorsements. They exist so that when Epic 1B changes this behaviour, the change is **visible and deliberate** rather than silent.

| Behaviour pinned | Debt ID |

| Hardcoded `False`/`True` flags in `main.py` make three filters unreachable | GG-002 |

| "No odds available" is the path all 39 committed fixtures took | GG-004 |

**These tests are expected to be updated when the behaviour is intentionally fixed.** That is the point of them.

## 5. Finding discovered during this Epic

Writing the invariant suite surfaced one behaviour not in the Epic 0 audit.

**Float64 saturation at extreme lambda.** Beyond λ ≈ 37.43, `1 - math.exp(-λ)` evaluates to *exactly* `1.0`. `P(GG)` is then reported as absolute certainty with no warning. Measured boundary: `λ=37.4` → `0.9999999999999999`; `λ=38.0` → `1.0`.

Reaching that λ requires absurd inputs, so this is **not a live production concern**. It matters because `POISSON_V1` applies **no upper bound to lambda** — a corrupt or mis-parsed statistic combined with a small league average could produce it. Recorded in `test_probability_saturates_to_exactly_one_at_extreme_lambda`.

**No numerical safeguard was added.** Reported, not fixed.

## 6. Tooling decisions

Both tools are configured to **report** legacy problems rather than force a rewrite of code this Epic must not touch.

**Ruff** — conservative rule set (`E4`, `E7`, `E9`, `F`, `I`, `B`). `UP` (pyupgrade) is deliberately **not** selected: it produces 94 findings across 12 of 13 legacy modules, all cosmetic (`Dict`→`dict`, `Optional[X]`→`X | None`). Enabling it would either fail CI permanently or force exactly the churn this Epic forbids. Turn it on during the Epic 2 `src/` migration.

Real findings suppressed per-file with an explanatory comment, each recorded in `TECHNICAL_DEBT.md`:

- 5 unused imports (`analyze_all.py`, `shared/odds.py`, `sofascore.py`)
- 3 f-strings with no placeholders (`analyze_all.py`)
- 2 `if x: return y` one-liners (`espn.py`)
- `sys.path` mutation before imports (`shared/odds.py`) — load-bearing, so import order left alone repo-wide

**mypy** — gradual adoption, checking the pure core plus tests. `decision.py` is excluded: its 13 errors all stem from **one** root cause, `make_decision` building a heterogeneous dict that mypy infers as `dict[str, list[Any] | str | float | None]`, which then rejects every `result["reasons"].append(...)`. Runtime behaviour is correct; this is a typing-expressiveness gap and precisely the weak-typing issue in GG-018. The proper fix is a `TypedDict`/dataclass — a production change deferred to Epic 1B. Behaviour is covered by 35 tests instead.

`run3/` is excluded from both tools so tooling can never prompt a change to parked code.

## 8. Spec disagreements kept visible

Epic 0 found five `GG.md` vs code disagreements. Each is a **product decision**, not a bug to fix unilaterally, so each is recorded as a permanently-skipped test in `test_spec_agreement.py`. They appear in every test run rather than only in a document:

| ID | Disagreement |
|---|---|
| D1 | `GG.md` names API-Football as primary; production uses ESPN |
| D2 | `GG.md` says missing data → NO BET; code accepts `0` as real |
| D3 | `GG.md` calls the five filters mandatory; three are hardcoded off |
| D4 | `GG.md` says goals *scored*; callers pass different quantities |
| D5 | `GG.md` treats league average as an input; it is always the `1.35` fallback |

The **core mathematics agrees with the spec** and is pinned by 17 passing tests, including a check that λ_home uses the *away* team's conceding rate (a transposed implementation would otherwise look plausible).
